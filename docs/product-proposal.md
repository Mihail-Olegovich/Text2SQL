# Product Proposal

## Обоснование идеи

Аналитические данные в крупных компаниях распределены по сотням таблиц с разрозненной документацией. Получение ответа на бизнес-вопрос требует участия аналитика: он должен найти нужную таблицу, разобраться в схеме, учесть бизнес-логику и написать корректный SQL. Это занимает часы или дни.

Проект реализует агента, который принимает вопрос на естественном языке и самостоятельно формирует SQL-запрос к нужной базе данных — без участия разработчика или аналитика.

## Цель и метрики

**Цель:** снизить время получения аналитического ответа с часов до минут для нетехнических пользователей.


| Категория   | Метрика                                                                    | Целевое значение |
| ----------- | -------------------------------------------------------------------------- | ---------------- |
| Агентская   | Execution Accuracy (EX) на бенчмарке [BIRD](https://bird-bench.github.io/) | >= 60%           |
| Агентская   | Среднее число шагов агента до финального SQL                               | <= 10            |
| Техническая | p95 latency                                                                | <= 120 с         |
| Техническая | Пиковый RPS                                                                | 10               |
| Продуктовая | Доля запросов, получивших ответ без ошибок выполнения SQL                  | >= 80%           |


Валидация производится на тренировочной и dev-выборках бенчмарка BIRD, который покрывает 95 баз данных и более 37 профессиональных доменов.

## Сценарии использования

**Основные:**

- Аналитик задаёт вопрос ("Сколько заказов было за последний месяц по каждому региону?") и получает SQL + результат без написания кода
- Менеджер проверяет метрику в незнакомой базе без обращения к дата-инженеру

**Edge-кейсы:**

- Вопрос затрагивает несколько баз данных одновременно — агент выбирает наиболее подходящую, результат может быть неполным
- Схема содержит "грязные" значения (нестандартные форматы, NULL-паттерны) — агент делает exploratory-запросы для проверки перед финальным SQL
- Вопрос сформулирован неоднозначно — агент фиксирует интерпретацию перед ответом
- База данных содержит много таблиц — агент итерирует по метаданным, время ответа может превышать p95

## Ограничения

**Технические:**

- Поддерживаемый диалект SQL: SQLite (в рамках PoC)
- Количество строк в результате: не более 50 на запрос

**Операционные:**

- Используются локальные языковые модели или модели через OpenRouter — затраты зависят от объёма токенов на один агентский цикл
- Инфраструктура PoC не рассчитана на production-нагрузку
